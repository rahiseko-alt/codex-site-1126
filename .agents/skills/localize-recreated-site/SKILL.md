# 既存サイトの日本向け差し替え

**既存のHTML・テンプレート・コンポーネントとCSS・JavaScriptを土台にして、指定された表示素材だけを差し替える。** 同じ業態とユーザーの導線を保ち、元の公開版と別のフォルダ・URLで管理する。

## 1. 土台を特定する

- ルートのサイト一覧から元のフォルダを探し、そのREADME、ソース、配信バンドル、公開版を確認する。
- 対象ページごとに、セクションの順番、PCとスマホの配置、画像の寸法とトリミング、ナビゲーション、フォームやリンクの挙動を確認する。見える画面とコードの両方を参照する。
- 演出は上から順に、対象、発火条件、方向、移動量、開始の遅延、時間、繰り返し、操作時の変化を記録する。自動送り、スクロール、ホバー、タップ、スワイプ、追従、ポップアップは対象ページにあるものを確認する。

## 2. 既存コードの差し替え箇所を使う

- 既存のマークアップ、セクション順、クラス・ID、演出用属性、余白、ブレークポイント、CSSのアニメーション定義、JavaScriptのイベント処理と設定値を引き継ぐ。テーマやバンドルをそのまま使い、値を差し替える箇所は差分で追える形にする。
- ブランド名、ナビゲーションやボタンのラベル、本文、代替テキスト、ページ情報を日本語に合わせる。価格や日時がある場合は、依頼に合わせて円・税込表記・日本時間（`Asia/Tokyo`）を使う。長い日本語は元の枠に収まる表現に調整する。
- 写真、ロゴ、イラスト、動画、GIFは、元の素材枠に合う縦横比、トリミング、視線の位置で用意する。PC・モバイル別画像、`srcset`、ホバー画像、ポップアップ画像にも差し替えを適用する。
- 配色は既存の色変数や値を置き換える。既存のHTMLとスタイルを使い、似た見た目や動きのために別のコンポーネントや演出スクリプトを追加しない。
- 別ブランドに持ち込めない外部連携がある場合は、必要な入力データやリンク先の変更を該当箇所に限定する。デモに置いた機能や、配信できない外部コンテンツはREADMEと報告に記載する。

## 3. 元の版と比較する

- 変更差分を確認し、セクション順、主要なDOM構造、演出用のクラス・属性・設定値が一致することを確認する。コピーした演出バンドルはファイル比較やハッシュで照合する。
- 同じブラウザ条件でPC幅・スマホ幅のスクリーンショットを撮り、枠、改行、切り抜き、余白、コンテンツの並びを見比べる。
- 静止画に加えて、スライドの前後やスクロールの途中を実際に操作する。動きの方向、時間差、自動送りの間隔、表示後の状態、リンクやフォームの遷移を確認する。公開した場合は公開URLでも確認する。

## 4. 単独で使える形にする

- `sites/<新しいサイト名>/` にコード、素材、差し替え箇所、起動・ビルド・検証手順、元URL、公開URLをまとめる。公開する場合は新しいサイトの公開設定を使う。ルートのREADMEには新しいサイトへの案内を加える。
- 最後に公開先、差し替え箇所、検証結果、個別に扱った外部連携や未検証の挙動を伝える。

実例は [nagi nail studio](../../../sites/nagi-nail-tokyo/README.md)。[構成と演出の検証記録](../../../sites/nagi-nail-tokyo/docs/design-qa.md)に、元のテーマを使った差し替えと確認方法を記載している。
