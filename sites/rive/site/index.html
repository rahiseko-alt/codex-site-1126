How to get started

Direct your agent. Then shape it by hand.

Start with one prompt in your coding agent. It installs the Rive CLI, builds a first version, and opens the CLI preview window on your screen, no account needed. Keep directing it, or open it in the Rive Editor for professional design and animation tools: rigging, timelines, state machines, and data binding.

Works with Claude Code, Codex, Cursor, and any agent that runs commands on your computer. macOS (Apple Silicon), Windows, and Linux.

Rive CLI

Rive, written in plain text

Rive, written in plain text

The CLI builds Rive files from Rive Markup Language (RML), plain-text .rml files that agents can read and write. No sign-in and no account needed to get started.

Check what you built

Confirm a scene compiles, inspect what it contains, render frames without a window, and drive it with real or simulated input and data. Run the same checks in CI.

Text you can diff

A project is a folder of plain text and assets, so it lives in Git or Perforce next to your app code, and every change reviews as a readable diff.

Work offline

Write, preview, verify, and test without a connection. Sign in to publish or sync with the Rive Editor. Publishing compiles and signs your scripts, and runtimes refuse any script that isn’t signed.

AnimaScript

Scripts your engineers can sign off on

Scripts your engineers can sign off on

AnimaScript is Rive’s scripting language: TypeScript syntax, compiled to WebAssembly. Edit the code below: the compiler runs in your browser.

Read the docs

See the benchmarks

Reviewed like your code

Every script is a .as text file in your repo. Engineers, Copilot, or your own agent review it in a pull request, with the same approvals as everything else you ship.

Signed

Publishing signs your scripts. Runtimes refuse scripts that are unsigned or changed after signing.

Sandboxed

Scripts run in a WebAssembly sandbox and only reach the Rive APIs the runtime gives them. A bad pointer stops the script instead of touching your app’s memory.

Tested in CI

Write tests next to your scripts and run them headless with rive --test. A failing test fails the build.

Near native speed

Compiled ahead of time, AnimaScript decodes Draco meshes 8.7× faster than the previous scripting runtime. Existing scripts keep working.

// Edit any number: the scene recompiles as you type.
declare function dot(x: f32, y: f32, r: f32, a: f32): void;

struct Vec2 {
    x: f32;
    y: f32;
}

function orbit(i: i32, t: f32): Vec2 {
    const k = <f32>i;
    const angle = t * (0.3 + k * 0.004) + k * 2.399;
    const radius = 16.0 + k * 0.42;
    let p = Vec2();
    p.x = Mathf.cos(angle) * radius;
    p.y = Mathf.sin(angle) * radius * 0.6;
    return p;
}

export function frame(t: f32): void {
    const count = 360;
    for (let i = 0; i < count; i++) {
        const p = orbit(i, t);
        const fade = <f32>i / <f32>count;
        dot(p.x, p.y, 1.0 + fade * 1.6, 0.25 + fade * 0.75);
    }
}

Rive or HTML?

Use the right tool for the job

Use the right tool for the job

Think of Rive as a game engine, but not just for games: it pays off when there’s a lot of motion and interactivity, especially if it ships on more than one platform. Agents, developers, designers, and animators all work in Rive, through the Rive CLI or the Editor. For many pages, plain HTML is still the right call.

Rive vs HTML

Use it whenRiveHTML
Your team builds it together: everyone works on the same production file, in the Rive Editor or as text with the Rive CLI, and several people can edit it in the Editor at once. Anyone can fix what they see instead of filing a change request, and Revision History keeps every version of the design.
It has to run smoothly everywhere you ship: it plays natively on web, iOS, Android, desktop, game engines, consoles, TVs, and cars, drawn by the same runtime.
You don't want a rewrite per platform: your agent edits it once, not separate web, Swift, and Kotlin code that drift apart.
You'd otherwise combine many libraries: rendering, layout, text, animation, 3D, audio, and input are built into one engine, so your agent uses them instead of writing and maintaining its own.
A lot moves at once: characters, layered vector animation, and interactive scenes that get heavy as DOM or SVG animation.
It's a game that should reach more than the browser: consoles, native mobile apps, and desktop, with no rewrite.
You want hands-on control: professional design and animation tools (Graph Editor, Timeline, bones and constraints, State Machine), made by the team that builds the format, runtimes, and Renderer, so every tool is made for what the runtimes play.
It's mostly text, documents, or forms on the web.
It needs to be found through search, like articles and docs.
It's a simple web-only effect your agent can write in a few lines of CSS.

Most websites use both. Rive drops into any web page, app, or game as one component.

Why teams choose Rive

Ship faster, spend less, build better

Ship faster, spend less, build better

Rive holds the design, code, and motion, and what you build is what ships. That one change cuts time to market and cost, and raises the bar on quality.

Faster time to market

Designers, animators, developers, and agents all work in Rive, so there’s no handoff and nothing to rebuild for each platform.

Agent speed, artist control

Your agent builds with the Rive CLI in Claude Code, Codex, or Cursor, in hours instead of weeks. Then your team refines it by hand in the Rive Editor, with professional tools for rigging, timelines, state machines, and data binding.

Lower cost

No revenue share, no runtime fees, no royalties, and MIT open-source runtimes. One engine covers every screen, from the car dashboard to the phone app, so there’s one thing to build, review, and maintain.

Higher quality

Vector, raster, and 3D in one scene, drawn by the Rive Renderer. It’s light enough for an underpowered car GPU, so you can build experiences where you wouldn’t run HTML or a full game engine.
